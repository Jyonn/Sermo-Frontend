# 友间前台语音通话：本地方案与交互原型

这是第一轮独立设计稿，保留用于对照。当前全屏、可折叠的正式组件预览位于前端开发服务 `/design/voice-calls`；后端实现及本地启动说明见 `sermo-backend/docs/foreground-voice-calls.md`。当前均未接入生产。

本目录原型入口 `index.html`，不读取登录态、不访问业务 API、不申请麦克风、不发送真实通知。原型人物、额度和时钟均为模拟；刷新恢复初始数据。演示台用于切换测试情境，不进入正式产品界面。

## 已确定的范围

一对一前台语音通话。双方均为 VIP；每人每周五分钟；成功拨打后出现语音通话气泡，并通过现有通知渠道发送来电通知。对方无额度时，发起前提示无法拨打。本阶段不建设锁屏、后台来电或系统接听界面。

## 建议采用的规则（本地方案默认值）

| 事项 | 规则 |
| --- | --- |
| VIP | 当前项目以 `User.is_permanent_vip` 判断资格，主叫、被叫均检查；不使用等级代替 VIP。资格在发起和接听时重新检查。 |
| 每人 | 推荐按已验证手机号对应的全局身份汇总，跨空间共用 300 秒，不能通过切换账号或空间重复领取；无验证手机号时先完成验证。只存身份摘要，不把手机号放进消息和通知。此口径需在正式实施前确认。 |
| 周期 | 北京时间每周一 00:00 重置，不结转。跨周通话在边界结束，避免一通电话隐式占用下一周额度。 |
| 扣减 | 主叫和被叫各扣实际接通时长。响铃、拒绝、取消和接通前失败不扣；静音与短暂重连继续计时。服务器按整通时长向上取整到秒，不逐段重复取整。 |
| 上限 | 单次最长取双方剩余时长与距本周结束时间的最小值；拨打前告诉主叫这个上限，不公开对方精确余额。 |
| 并发 | 同一人至多一通响铃或活动通话；跨设备、跨空间也适用。双方同时互拨时返回已有会话，仍须明确接听，不能自动接通。 |
| 通知 | 尊重原有通知渠道选择、静音与隐私设置；独立的来电事件立即入队，不能等待普通离线消息汇总。通知链接只带记录 ID，打开后重新验证身份和实时状态。 |
| 会话权限 | 仅已有可正常发消息的私聊，沿用现有成员、屏蔽与消息权限；群聊不提供入口。VIP、忙线或余额检查失败时不生成气泡或推送。 |
| 前台边界 | 正式版进入后台或锁屏就请求结束通话；服务端依据前台心跳丢失兜底结束。不能承诺后台事件必达或瞬时断开。来电通知可引导用户打开应用，在响铃有效期内接听。 |

## 交互设计

单聊顶栏使用现有线性电话图标。点击打开共享 BottomSheet：显示“和某某聊一会儿”、本次最长时长、双方计时说明，再确认拨打。先预检资格，用户确认后申请麦克风，授权成功才提交创建；提交时服务端再次校验，避免权限失败留下虚假来电记录。麦克风拒绝以持续提示展示重试说明。

被叫收到全局应用内来电 Sheet，展示头像、姓名、最大可用时长、拒绝与接听。保持输入草稿；来电不是自动接通。点接听申请麦克风，成功后确认加入。未接听 30 秒结束；建立媒体连接超过 15 秒结束，不扣接通前费用。

通话中显示已通话时长、剩余时间、静音和挂断。可以收起成应用内常驻通话条，切换站内页面仍可返回通话；前台通话不依赖聊天页面存活。最后 15 秒持续提示，归零由服务端关闭媒体。iOS 暂不承诺网页控制听筒/扬声器，输出切换只在浏览器实际支持时提供。

一通电话只生成一条气泡，持续更新：等待接听 → 通话中 → 通话时长；终止结果包括已取消、未接听、已拒绝、连接失败、连接中断、额度用尽。气泡点击在活动时返回通话，结束后进入新的拨打确认。历史记录不携带入会凭证；不能通过转发气泡加入通话。状态变化不重复增加未读或重复推送。

现有两分钟在线判定不能证明对方现在能接听。来电通过独立的前台同步发现；在线徽标仅供参考。对方未在前台也可收到已启用渠道的通知，打开后仅在仍有效、仍有额度时接听；过期页面只展示通话结果。

## 对接现有项目

已核对前端 `ChatQuickActions`、聊天交互规范、现有录音入口，以及后端 `User.is_permanent_vip`、`NotificationEvent.emit_message_notifications`、`MessageEvent`。录音消息 `AUDIO` 与实时通话不同，新增服务端专用消息类型 `VOICE_CALL`，客户端不得伪造通话状态。

建议新增 `VoiceCallProvider`（登录后挂载一次）、共享通话 Sheet、通话条、聊天气泡渲染适配。正式实现沿用 BottomSheet、全局通知、翻译键与既有颜色变量，避免各页面复制一套通话 UI。此目录中的独立样式只用于本地评审，不是新的生产组件系统。

后端新增共享通话策略服务，统一资格展示与创建/接听的最终校验。API 建议：

| 接口 | 用途 |
| --- | --- |
| `GET /voice/capability?chat_id=…` | 我的剩余额度、能否拨打、原因码、最大通话秒数；不返回对方精确余额。 |
| `POST /voice/calls` | 幂等键 + 私聊 ID；原子校验、占用双方额度、创建呼叫/单条消息/通知 outbox。 |
| `GET /voice/calls/current` | 获取当前人的活动来电/通话；支持游标，无会话时轻量返回。 |
| `POST /voice/calls/{id}/accept` | 校验被叫身份、有效期、VIP、额度；返回短期、限定房间与身份的媒体令牌。 |
| `POST /voice/calls/{id}/decline` / `end` | 幂等终止；任何参与者可结束自己的当前通话。 |
| `POST /voice/calls/{id}/heartbeat` | 前台心跳与客户端状态；不能由客户端报告的时长决定扣费。 |

建议首版复用 REST 同步：应用前台每 3 秒拉取活动来电，响铃/通话时每秒同步状态并发心跳；后台停止轮询。现有会话列表的 15 秒轮询不承担来电信令。邀请发现延迟约 0–3 秒，正式上线前评估是否改用长轮询或 WebSocket。媒体连接使用媒体引擎自己的实时链路。

## 媒体与额度的服务端保障

采用 WebRTC 音频及具备服务端房间控制能力的媒体服务，首选验证 LiveKit；只允许两个指定身份发布音频，禁用视频与额外参与者。服务端必须能够到时强制终止媒体并拒绝旧凭证重入，不能只依赖页面倒计时。浏览器退出后仍能通过服务端清理资源。

LiveKit 令牌过期不会中断已经建立的连接。官方 Cloud 的 DeleteRoom 有当前令牌撤销机制；自托管不能直接假设同样语义。选型验证必须覆盖关闭房间后的旧令牌重入、房间被重新创建、重复身份、延迟 webhook 和媒体中断计费；若自托管无法保证终止后的准入撤销，应补受控准入层或更换媒体方案，不能宣称额度已严格实施。本方案不申请云资源，不发生外部服务费用。

建议数据模型：`VoiceCall` 存双方身份、chat/message ID、状态、连接起点、强制截止点、结束原因与结算标记；`VoiceWeeklyQuota` 按身份摘要和周唯一，存已使用/预留秒数；`VoiceQuotaLedger` 按 call + 身份 + 周唯一；`VoiceCallOccupancy` 以身份唯一约束跨设备并发。通知采用现有 delivery/outbox 的幂等模式。

创建时按稳定顺序锁双方身份和额度行；预留本次最大可用秒数，响铃期间不会实际扣费。连接开始以媒体服务证实双方已连接并可传音频为准，记录唯一开始时刻和截止时刻。可靠的服务端每秒 watchdog 扫描到期/断联通话，执行媒体关闭、原子结算和事件更新；进程重启后可恢复扫描。webhook 做签名验证、去重和顺序检查，不能因为重复通知重复扣费。

结束事务将实际秒数写入双方账本并释放未使用预留；断联保守按服务端最后证实连接状态与超时策略结算，不接受客户端伪造的起止时间。前台心跳超过 8 秒丢失结束；媒体短暂重连最多 10 秒，期间继续计时。若暂时无法关闭媒体，保持清理重试并阻止重入，用户扣费不超过已预留上限。

通知事件使用 `voice_call.invited`，复用现有渠道、私隐、静音和路由策略，但独立处理有效期与即时投递。事件只投递一次，重试不得越过呼叫有效期；内容包含谁来电及打开友间的入口，不包含令牌。通话气泡需新增消息更新事件（现有事件主要为创建/隐藏/撤回/恢复），各端依版本更新同一记录，不滥用 created 引发重复通知。

## 本地原型评审

运行：在本目录执行 `python3 -m http.server 8788 --bind 127.0.0.1`，浏览器打开 `http://127.0.0.1:8788/`。无需登录，可切深浅色和中英文。支持主叫确认、模拟对方接听/拒绝/超时、来电接听/拒绝、计时、静音、收起、返回、重连/恢复、额度自动结束、再次拨打及阻断情境。原型在后台的定时器不用于验证真实前台断线策略。

验收正式接入前必须覆盖：双方资格、被叫无额度、跨空间汇总、互拨并发、余额预留/释放、秒级幂等扣减、跨周、VIP 变化、过期通知、拒绝麦克风、iOS 前台扬声与权限、切后台/锁屏退出、断网/重连、服务重启、伪造和过期媒体令牌，以及手机/桌面、深浅色、安全区和键盘操作。真实 iPhone PWA 前台媒体链路必须实机验收，Chrome 模拟不能替代。

建议先评审交互与本页规则，再实现后端账本/通知与媒体终止验证，最后接入正式前端。当前文件不会在聊天页增加入口，不发布前端新版本。
